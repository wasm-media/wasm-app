# الشريحة 0 — البنية التحتية (0أ ثم 0ب)

**الحالة:** جولة الصفر تمّت 24/09/2026 (مراجع مستقل) ← الشريحة قُسمت لاثنتين لأنها أكبر من يومي عمل ← **اعتمدهما عيسى («موافق» 25/09/2026 00:02).** 0أ محجوبة بـP1 (DEFERRED).

## قرار المنفّذ على ملاحظة واحدة من جولة الصفر (موثّق)
المراجع اقترح أن يقبل الحارس تقرير المراجع فقط إذا جاء من حساب مراجع لا يملكه المنفّذ. **لا يُطبَّق:** المراجع الآلي وكيل Claude يعمل في الجلسة نفسها، فأي حساب له يكون تحت يد المنفّذ عمليًا، وفحص «حساب مختلف» يصير فحصًا شكليًا يوهم بضمان غير موجود (MISTAKES N2). **البديل الصادق:** الحارس يتحقق فقط أن التقرير على رقم آخر commit. الضمانة الملزمة هي ضغطة عيسى + CI. (مراجعة ChatGPT أُلغيت بـD20.)

المستخدم يستطيع: عيسى يرى على كل PR فحصَي ci وguard، ولا يُدمج شيء إلا بضغطة Approve منه
لا يستطيع:

- بلا دخول: رؤية المستودع
يُقبل إذا:
(1) أقفال main — كل واحد بمحاولة فعلية مرفوضة، والأمر ومخرجه في reviews/:

  1.2 صلاحية المنفّذ = write؛ دفعه المباشر وforce-push وحذف main تُرفض

  1.4 PR أخضر + Approve عيسى ← commit جديد ← الدمج يُرفض حتى Approve جديد
  1.5 موافقة من غير حساب عيسى لا تكفي (CODEOWNERS = عيسى)

  2.1 يعدّل workflow الحارس ليخرج 0 · 2.2 يضيف job اسمه guard ينجح · 2.3 ينشر حالة guard=success عبر API
  2.4 يحذف اختبارًا · 2.5 يعلّم اختبارًا skip
  2.6 يلمس ملفات الحراسة (.github/، CODEOWNERS، ملف العدّ، إعدادات مشغّل الاختبارات، الملفات الحاكمة) — فئة بفئة
  2.7 تقرير «معتمد» على hash غير آخر commit

  2.9 guard لا يشغّل كود الـPR ولا يحمل أي سر

  3.1 فرع تجريبي: job بـenvironment: production يرفضه GitHub، وjob بلا بيئة يقرأ كل سر إنتاج باسمه = فارغ
  3.2 الـworkflow نفسه على main يطبع present لكل سر (لا القيمة)
  3.3 الملفات الحاكمة موجودة على main
خارج النطاق: قاعدة البيانات، النسخ، الواجهة، النشر لأي خادم · إثبات هوية كاتب تقرير المراجع (انظر القرار أعلاه)

## التجهيز اللي بيعمله عيسى بإيده (إنشاء الحسابات والدفع ما بيعملهم Claude)
1. حساب GitHub الشخصي لعيسى.
2. منظمة GitHub بخطة Team + الدفع.
3. مستودع خاص `wasm-app` داخل المنظمة مع README (هذا أول commit على main باسم عيسى).
4. حساب GitHub ثانٍ للمنفّذ بإيميل ثانٍ، مدعو للمستودع بصلاحية Write — وتسجيل دخول Claude فيه يتم برمز لمرة واحدة يدخله عيسى بنفسه، فلا يرى Claude أي كلمة سر أو token.
5. حساب Supabase ثانٍ بإيميل غير بريد عيسى الأساسي، فيه مشروع الإنتاج — كلمة سر القاعدة تبقى عند عيسى، ويضعها بنفسه في أسرار GitHub عند 0ب.
